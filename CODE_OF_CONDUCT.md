# Code of conduct

## The short version

Be decent. Argue with the code, not with the person holding it.

## What is expected

Technical disagreement is the point of this project and is welcome without limit. Several
decisions here were reversed because someone was right — a rule withdrawn rather than shipped
on a supposition, a guard that was found to pass on the very defect it was written for. Saying
"this is wrong, and here is why" is a contribution.

What is expected alongside it:

- **Bring evidence.** A measurement beats an opinion, and "I have not checked" is a complete
  and respectable sentence. This repository distinguishes throughout between what was observed
  and what was deduced; conversations here work the same way.
- **Assume competence.** People make mistakes without being careless.
- **Accept being corrected**, including publicly. It is not an attack.

## What is not accepted

Harassment, insults, or personal attacks. Sexual, racist, or otherwise demeaning language.
Publishing anyone's private information. Persistently pushing past a clear "no".

None of this becomes acceptable because the technical point underneath happens to be correct.

## A note specific to this project

Rempart audits machines, and reports about it can carry sensitive material — a capture names
software, network configuration and weaknesses. **Do not post someone else's capture, report,
or machine details** without their explicit agreement, even to make a point about a bug.
`rempart capture` anonymises by default; that is not permission to share what is not yours.

Suspect a vulnerability rather than a bug? It does not belong in a public issue. See
[SECURITY.md](SECURITY.md) — private reporting is enabled and reaches the maintainer directly.

## Scope and enforcement

This applies to issues, pull requests, discussions, and any space where someone represents the
project.

Report a problem through
[private security advisory](https://github.com/naoutix/rempart/security/advisories/new), which
is the one private channel this repository has, or directly to
[@naoutix](https://github.com/naoutix). Reports are handled confidentially.

The maintainer may edit or delete content, and block accounts, in response to behaviour that
breaks this document. There is no appeal process, because there is no committee — this is a
small project, and pretending otherwise would be a fiction.
